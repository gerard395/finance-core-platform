# P3-001 – Purchase Authorization & Posting Configuration

## Scope en resultaat

P3-001 levert uitsluitend de productfoundation voor latere domestic PurchaseInvoice-
stories. Er is nog geen PurchaseInvoice-persistence, lifecycle, Webflow, posting,
JournalEntry, TaxPosting, Payable, credit of payment.

## Authorization

De onafhankelijke typed permissions zijn `PURCHASING.VIEW`,
`PURCHASING.INVOICES_DRAFT_MANAGE`, `PURCHASING.INVOICES_FINALIZE` en
`PURCHASING.INVOICES_POST`. De canonieke rol `PURCHASING_MANAGER` bevat View,
DraftManage en Finalize; `PURCHASING_POSTER` bevat View en Post. Permission-, role- en
role-permission-identiteiten zijn stabiel. Provisioning is transactioneel,
create-missing-only/collision-safe en maakt nooit users, memberships of membership-role
assignments. Authorization blijft per actieve Administration-membership en per request;
rolnamen zijn geen authorizationmechanisme.

## PurchasePostingConfiguration

Een Administration bezit maximaal één configuration met exact een actief same-tenant
Purchase Journal, een actieve same-tenant Liability als Accounts Payable en een actieve
same-tenant Asset als Input VAT. Hard samengestelde tenant-FK's voorkomen cross-tenant
references. De typed reader retourneert `Missing`, `Success` of `InvalidReference` en
benoemt bij InvalidReference iedere onbruikbare reference. Deactivatie blijft toegestaan
en geeft geen automatische replacement. Een transactionele volledige update valideert
alle references vóór de ene persistencewrite; bij failure blijft de oude configuration
intact. Er bestaat geen default expense account.

Beheer → Instellingen bevat de sectie **Inkoopboekingen**. Selectors tonen uitsluitend
active same-tenant Purchase/Liability/Asset masterdata. Journal en accounts worden via
het bestaande W4D-beheer gemaakt. De route gebruikt uitsluitend
`ADMINISTRATION.SETTINGS_UPDATE`; body-tenantdata wordt genegeerd.

## Domestic Input VAT catalogue

De expliciete productmatige settingsactie maakt create-missing-only de volgende actieve
Input-codes beschikbaar:

| Code | Naam | Tarief | Treatment | VAT-return | ICP |
| --- | --- | ---: | --- | --- | --- |
| `INBTW21` | Voorbelasting hoog (21%) | 21 | domestic_standard | domestic_standard | none |
| `INBTW9` | Voorbelasting laag (9%) | 9 | domestic_reduced | domestic_reduced | none |
| `INBTW0` | Inkoop binnenland 0% | 0 | zero_rated | domestic_zero_rated | none |
| `INVRIJ` | Inkoop vrijgesteld | 0 | exempt | exempt | none |
| `INBUITEN` | Inkoop buiten btw-scope | 0 | outside_scope | outside_scope | none |

Identiteiten zijn deterministisch per Administration en code. Compatible bestaande
state, inclusief naam/status/timestamps, wordt behouden; rate/direction/classification-
conflicten stoppen de volledige transactie. Output-codes wijzigen niet. De catalogus
selecteert nooit automatisch een TaxCode. Positive VAT is uitsluitend volledig
aftrekbare domestic Input VAT; partial/non-deductible, EU/import/foreign/reverse-charge
en VAT/ICP-reporting blijven uitgesloten.

## Empty Administration setup

Een settingsbeheerder kan zonder SQL of developmentcommand via W4D een Purchase
Journal, AP Liability, Input VAT Asset en Expense/Asset-lineaccount maken, via de
settingsactie de Input-catalogus beschikbaar maken en daarna de configuration opslaan.
De typed reader geeft vervolgens `Success`. Daarmee is P3-002 foundation-ready, zonder
dat P3-001 al een PurchaseInvoice introduceert.
