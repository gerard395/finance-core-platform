# W1-004 – Dashboard Presentation Foundation

## Status and inventory

**Implemented.** The earlier dashboard blocker was resolved by the tenant-scoped read persistence in W1-003B/C/D/E and the explicit Accounting-owned `OpenItemType` from W1-003E0.

`GetDashboardOverview` is one read-only Application use case. It receives `AdministrationId`, typed period start/end and Currency and returns typed `DashboardOverview` containing the same context plus exact Money for revenue, outstanding receivables, outstanding payables and VAT position. It has no authentication/User input and no formatting responsibility.

The controller receives the already authorized `ActiveAdministrationContext` from W1-002 middleware. It never accepts tenant context from query/form input. The active Domain Administration supplies both `AdministrationId` and its factual `baseCurrency()`; no EUR or other fallback is invented.

## Financial source truth and reporting reuse

Revenue uses `LedgerAccountReadRepository` and `JournalEntryReadRepository::findPostedForAdministrationAndPeriod()`, then the existing `TrialBalance` and `ProfitAndLoss`; the dashboard reads only `ProfitAndLossResult::totalRevenue()`.

Open items use `OpenItemReadRepository::findForAdministrationAsOf()`. The use case partitions the returned Domain objects by the explicit immutable `OpenItem::type()`, passes each partition to `OpenItemsReport`, and reads `totalOpenAmount()`. Receivable feeds outstanding receivables and Payable feeds outstanding payables. `OpenItemsReport` remains the sole source of historical settlement/status arithmetic and excludes Closed items. Customer/Supplier classification is not queried and no sign, account, document or Relation heuristic exists.

VAT uses `TaxPostingReadRepository::findForAdministrationAndPeriod()`, existing `VatOverview`, and only `VatOverviewResult::netVatPosition()`. Input/Output and Original/Reversal arithmetic remain in Reporting.

Thus Application reuses and does not reimplement debit/credit aggregation, Trial Balance, P&L, settlement history or VAT netting. Empty repository results naturally produce four `Money::zero(currency)` values through the Reporting APIs.

## Period, timezone and presentation

For W1 v1 the controller derives today and the first day of the current calendar month server-side using the existing application timezone, currently UTC. Browser JavaScript supplies no financial date. Administration-specific timezone and Dutch locale configuration remain future product concerns.

`DashboardController` passes the typed overview to Blade. Four responsive cards show current-month revenue, receivables as of today, payables as of today and neutral VAT position, plus an explicit date range. Placeholder, percentage, trend, comparison and graph text is absent.

`DutchMoneyFormatter` is Presentation-only. It transforms the exact Money decimal string into a Dutch display string with visible ISO Currency, dot thousands separators and comma decimals, preserving up to all eight factual decimals. It never converts to float, rounds or performs financial arithmetic. Negative VAT displays with its minus sign and no unsupported legal interpretation.

## Tenant isolation and verification

Every repository call receives the authorized Administration ID. Existing adapters filter in SQL. Application tests additionally supply Draft, out-of-period and other-Administration facts and prove existing Reporting excludes them. The vertical feature flow uses real persistence adapters and proves all four values for the active Administration; switching the authorized session context from Administration A to B changes all reads and exposes no A value in B.

Tests cover empty state, posted-only current-period revenue, OpenItemType separation, partial/closed historical open amounts, positive and negative VAT, reversal netting, exact Currency, formatting, real dashboard values, period label, active Administration, placeholder/trend absence, guest redirect, missing/revoked context, A/B switching and tenant isolation. The known `phpunit.xml` Integration-suite gap is deliberately deferred to W1-005.
