## Authentication and auth bridge

Laravel's `web` guard and `Auth::attempt()` own password verification; application code never compares plaintext. Login normalizes email, combines email and IP in a five-attempt/60-second rate-limit key, returns the same Dutch error for unknown email, wrong password, broken bridge and inactive Domain User, clears the limiter only after complete success, and never provisions during login. Successful login regenerates the session ID. Failed post-auth Domain resolution and POST-only logout call `Auth::logout()`, invalidate the session and regenerate CSRF token. Login, Administration selection/switch and logout POST forms use Blade `@csrf`.

Laravel `users.id` remains the technical integer auth identity. Required unique `users.domain_user_id` is a restrictive FK to the UUID Domain User identity. `DomainUserResolver` resolves only that bridge—never email—and safely rejects missing/malformed/orphaned state. `ProvisionUserAccount` marks plaintext as sensitive, hashes through Laravel, and creates Domain plus auth records within the configured database transaction; unique database constraints are the final concurrency guard. Auth records hide password/remember token and no reviewed path logs passwords.

## Session, tenant and authorization boundary

The request chain is Laravel authenticated User → bridge-resolved active Domain User → untrusted session `active_administration_id` → UUID parse → current active Administration and currently valid active Membership → freshly loaded effective permissions → immutable request attribute context → Application.

The session ID is not authorization evidence. Membership and Administration status are checked on every `/app` request, so revocation is effective on the next request. Malformed/stale selection is removed. The single selection/switch POST reuses the same resolver; failed selection leaves the prior valid context intact. Logout invalidates the whole session, including tenant selection. Repository queries and financial foreign keys remain Administration-scoped; feature and integration tests prove A/B separation.

Roles and Permissions are system definitions, but their grants flow only through an AdministrationMembership. There are no direct User permissions. W1's only enabled destination is the read-only dashboard and its explicit current policy is active valid Membership access; disabled navigation is UX only. Before enabling later business modules, each route/use case needs an authoritative permission-code mapping and backend enforcement. That future mapping is non-blocking for this completed W1 surface.

Session cookies default to HttpOnly and SameSite Lax; Secure is production-configurable through `SESSION_SECURE_COOKIE`. Default idle lifetime is 120 minutes. Session fixation and stale authorization protections are active. Remember-me is deliberately disabled. Product decisions still open: final inactivity policy, MFA (especially elevated users), password-reset mail/UI, Administration timezone/locale and elevated/system access with audit requirements.

## Architecture and financial integrity

Domain and Application contain no Laravel/Eloquent dependencies. Presentation performs no Eloquent query or financial arithmetic. Controllers consume middleware context and call one Application use case; Blade uses escaped output and a string-only Money formatter with no float conversion. Limited native JavaScript only controls the responsive drawer.

Infrastructure implements narrow ports. `JournalEntry::reconstitute()` restores typed snapshots and validates Posted state without lifecycle replay; Posted persistence is insert-only and restrictive. `OpenItem::reconstitute()` restores immutable basis plus complete append-only settlement history; open amount/status are not columns, Reversal never replaces Applied, and as-of arithmetic stays in Domain/Reporting. TaxPosting is insert-only with database-unique identity, one-reversal constraint, exact TaxRate/Money strings and same-tenant entry/line references. Financial deletions are restrictive.

Relations have explicit persistence tenant ownership and same-tenant Customer/Supplier links. Overlap is allowed. Financial side comes exclusively from required persisted `OpenItemType`, never relation classification.

Dashboard revenue is `TrialBalance → ProfitAndLoss`; receivables/payables are `OpenItemType → OpenItemsReport`; VAT is `VatOverview`. Currency comes from active Administration, dates are server-side in the configured timezone, empty state is exact zero Money, and negative VAT is displayed neutrally. No duplicate financial algorithm exists in Application, controller or Blade.

Eloquent models use explicit fillable fields and safe date/boolean/hash casts; Money/TaxRate never use float casts. Queries use bound query-builder values, not interpolated user SQL. UUID primary/unique keys, ownership FKs, composite tenant FKs and restrictive deletes are ordered and covered by fresh-schema Integration tests.

Blade escaping remains intact; no raw output/eval/innerHTML was found. Redirects use named internal routes. POST routes have CSRF. The shell has a skip link, semantic navigation, ARIA state, Escape/backdrop close, focus movement/rings and responsive layout. Vite builds without a framework dependency.
