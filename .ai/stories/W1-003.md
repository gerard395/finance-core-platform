# W1-003 – Responsive Application Shell

## Status en inventory

**Status:** Implemented

W1-001D supplied standalone login/placeholder views; W1-002 supplies a request-scoped Domain User, active Administration and effective PermissionIds. Tailwind CSS 4, Vite and an empty native JS entrypoint were present. No layout/components or frontend framework existed.

## Shell architecture

`components/layouts/app.blade.php` owns the authenticated shell: dark semantic sidebar/navigation, sticky topbar, Administration indicator/switch, user/logout actions and main content slot. Small navigation section/item components provide active and disabled states. `/app` is the first consumer.

Desktop keeps the sidebar visible. Tablet/mobile use a native-JavaScript drawer with backdrop, `aria-expanded`, Escape close behavior and focus movement. Content becomes a responsive one/two/four-column grid. Controls have touch-sized targets and visible focus rings; a skip link and `aria-current="page"` identify navigation state beyond color.

## Navigation and permissions

Dashboard is the only enabled destination and is active on `/app`. The complete planned structure is visible as non-clickable, `aria-disabled` placeholders; no fake routes exist. The current permission catalogue has business names but no authoritative provisioned web permission-code mapping. W1-003 therefore invents no codes and performs no authorization in Blade. The request-scoped PermissionIds remain available for a later centralized mapping; backend authorization remains mandatory.

## Dashboard placeholder and patterns

The Dashboard shows welcome/context plus four cards—Omzet, Openstaande debiteuren, Openstaande crediteuren and BTW-positie—each explicitly labelled `Nog geen data gekoppeld`; no fictional amounts are rendered. White panels on a light background, restrained blue accent, dark navigation and consistent spacing establish the visual base. Empty data uses explanatory muted text; validation uses the existing inline alert pattern, while forbidden/system error pages remain later scope.

## Files and validation intent

The shell uses Blade escaping, existing CSRF logout/switch flows, Tailwind/Vite and limited `resources/js/app.js`; no dependency was added. Feature coverage verifies context, active navigation, semantic/mobile controls, disabled future items, security redirects/revocation inherited from W1-002 and explicit non-financial placeholders. The known phpunit Integration discovery gap remains for W1-005.
