# S4-000 – Sales Capability Design

## Doel

De aggregategrenzen, workflows, businessregels, domain events en architectuurregels van de Sales Capability vastleggen voordat implementatiestories starten.

## Capability

Sales

## Aggregates

- `Quotation` met child entity `QuotationLine`.
- `Order` met child entity `OrderLine`.
- `SalesInvoice` met child entity `SalesInvoiceLine`.
- `SalesCreditInvoice` met child entity `SalesCreditInvoiceLine`.

## Workflows

### Quotation

```text
Draft → Sent → Accepted → OrderCreated
Draft → Sent → Rejected
```

### Order

```text
Draft → Confirmed → PartiallyInvoiced → FullyInvoiced
```

### SalesInvoice

```text
Draft → Finalized → Posted → Paid
```

## Businessregels

- Iedere Quotation heeft minimaal één QuotationLine.
- Een Order ontstaat uit een geaccepteerde Quotation of wordt direct aangemaakt.
- Een SalesInvoice ontstaat uit een Order.
- SalesInvoice en SalesCreditInvoice krijgen hun definitieve nummer uit NumberSequence.
- Boekhoudkundige boekingen worden pas later door de Posting Engine uitgevoerd.

## Domain Events

- `QuotationCreated`
- `QuotationSent`
- `QuotationAccepted`
- `QuotationRejected`
- `OrderCreated`
- `OrderConfirmed`
- `SalesInvoiceCreated`
- `SalesInvoiceFinalized`
- `SalesInvoicePosted`
- `SalesInvoicePaid`

## Architectuurregels

- Aggregates wijzigen elkaars status nooit rechtstreeks.
- Iedere statusovergang verloopt uitsluitend via een domeinmethode van het betreffende aggregate.
- Orchestratie tussen Quotation, Order, SalesInvoice en andere capabilities vindt later plaats in de Application-laag.
- NumberSequence levert nummers maar bestuurt geen Sales-status.
- De Posting Engine boekt financiële gevolgen maar behoort niet tot deze ontwerpstory.
