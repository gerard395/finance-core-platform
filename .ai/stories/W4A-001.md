# W4A-001 — Quotation → Order Persistence/Application Conversion

## Implementatie

`CreateOrderFromQuotation` is de frameworkonafhankelijke transaction owner. Input is
uitsluitend AdministrationId, QuotationId en expliciete OrderDate. De use case lockt
de Quotation tenant-scoped via `QuotationOrderConversionSource`, accepteert alleen
`QuotationStatus::Accepted`, controleert via `OrderBySourceQuotationRepository` of de
bron al is geconverteerd en alloceert daarna een bestaand `SalesNumberType::Order`-
nummer binnen dezelfde database-transactie.

`QuotationOrderConversionIdentityGenerator` maakt een nieuwe OrderId en voor iedere
QuotationLine een nieuwe OrderLineId. CustomerId en de volledige immutable
SalesCustomerSnapshot, Currency, description, Quantity en Money unit price worden
rechtstreeks uit de Quotation gekopieerd. Er vindt geen live Customer/Relation-lookup,
floatconversie of Presentation-rekenwerk plaats. Na constructie moet Order-total exact
gelijk zijn aan Quotation-total. De Order start Draft, verwijst exact via
sourceQuotationId en de Quotation blijft Accepted.

Typed resultaten zijn Success(OrderId), NotFound, InvalidSourceState,
AlreadyConverted (met bestaande OrderId waar beschikbaar), SequenceMissing,
SequenceInactive, DuplicateIdentity en PersistenceConflict. Persistenceconflicten
gooien binnen de outer transaction een interne typed failure, zodat een reeds
gealloceerd nummer terugrolt. Order-create blijft insert-only; er is geen upsert.

## Database en concurrency

Migration 000036 voegt uitsluitend de korte unique index
`orders_source_quotation_unique` toe op
`(administration_id, source_quotation_id)`. MySQL laat meerdere NULL-waarden in deze
index toe, zodat directe Orders ongewijzigd blijven werken. De bestaande same-tenant
source-Quotation-FK blijft leidend. Infrastructure classificeert een non-null source-
duplicate als `OrderWriteResult::AlreadyConverted`; SQLSTATE en constraintnamen lekken
niet naar Application.

Lockvolgorde is source Quotation `FOR UPDATE`, bestaande source-Order lookup,
Ordernummersequence-lock, daarna Order/lines inserts. Twee gelijktijdige calls op
dezelfde Accepted Quotation serialiseren op de source row; database-uniciteit blijft
de harde tweede guard. De echte MySQL two-process test bewijst exact één Success, één
AlreadyConverted, één committed OrderNumber, één Draft Order, één regelsset en een
ongewijzigde Accepted Quotation.

## Tests en compatibiliteit

Gerichte Application/integratietests bewijzen Accepted conversie, alle vier ongeldige
source-statussen, tenant NotFound, historical snapshot na rename/deactivation, exacte
Currency/regelinhoud/totalen, nieuwe line-identiteit, sequential idempotency,
persistence-rollback en concurrency. Twee directe Orders met null source blijven naast
elkaar toegestaan. Er zijn geen routes, controllers, Blade- of navigatiewijzigingen;
de Web-action volgt in W4A-002.
