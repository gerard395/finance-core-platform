# W1-003D – Fiscal TaxPosting Read Persistence

## Status and Fiscal inventory

**Implemented.** `TaxPosting` is a readonly immutable fact whose constructor accepts its complete state: TaxPosting/Administration/TaxCode IDs, exact TaxRate snapshot, taxable-base and tax Money, Input/Output direction, source document type/ID/line ID, PostingDate, JournalEntry and base/tax line IDs, Original/Reversal type and optional reversed TaxPosting ID. The constructor enforces same Currency, non-negative amounts, positive-tax/tax-line and zero-tax/no-tax-line consistency, and Original/Reversal reference shape. It therefore safely hydrates persisted rows directly without lifecycle or policy replay.

`TaxPostingIdentityPolicy` remains Application/Fiscal preflight against supplied history. `TaxPostingReversalPolicy` remains command validation: Original target existence, single reversal and exact Administration/direction/code/rate/Money snapshot equivalence. Persistence does not replay those policies during hydration or recalculate fiscal truth.

## Schema and exact values

Migration `000014` adds `tax_postings` with every factual field and no VAT totals or Reporting summaries. UUID is the primary identity. TaxRate is its canonical decimal string (maximum four decimals) and both Money values use the established unbounded exact text-string pattern plus one `CHAR(3)` Currency. No FLOAT, DOUBLE, PHP float, rounding or rate recalculation occurs.

The migration adds a supporting `(administration_id, journal_entry_id, id)` candidate key to W1-003B lines. Composite restrictive foreign keys then prove that the JournalEntry, base line and optional tax line all belong to the posting's Administration and that both lines belong to that exact entry. The Reversal self-reference uses `(administration_id, reversed_tax_posting_id)` and cannot cross tenants. A nullable unique target constraint permits at most one persisted Reversal per Original. There is no cascade delete.

## Contracts, adapter and immutability

The narrow ports are:

- `TaxPostingStore::append(TaxPosting)`;
- `TaxPostingReadRepository::findForAdministrationAndPeriod(AdministrationId, PostingDate, PostingDate)`.

`EloquentTaxPostingRepository` is bound in `AppServiceProvider`. Append is insert-only: it rejects an existing primary identity, requires a Posted same-tenant JournalEntry and exact same-entry base/tax lines, and requires a Reversal target to be an Original in the same Administration. Database primary uniqueness is the concurrency-safe persistence safety net behind the existing in-memory identity policy. No save/upsert/update/delete API exists; Original remains unchanged and Reversal is a new row.

The read query applies Administration and inclusive period boundaries in SQL, includes every direction/type and 0% row, then orders by PostingDate and TaxPostingId. Every row is passed directly to the immutable Domain constructor with exact strings and value objects. No VAT arithmetic exists in Eloquent or Application contracts.

## Reversal audit and Reporting

Original and Reversal retain independent source document, PostingDate and Accounting references. The Reversal points to—but never mutates or replaces—the Original and is selected in its own period. Nullable tax lines preserve 0% Original/Reversal semantics.

Hydrated Output, Input, 0%, multiple-rate and Reversal facts feed `VatOverview` directly. Existing Reporting remains solely responsible for grouping and exact `totalOutputTax - totalInputTax`, including reversal netting.

## Verification coverage

Infrastructure integration tests cover complete Original snapshot roundtrip, exact eight-decimal Money, exact historical TaxRate, Input/Output, 0% with null tax line, Original/Reversal audit chain and separate periods, inclusive bounds, deterministic ordering, A/B isolation, duplicate identity, invalid/cross-tenant reversal target, cross-tenant entry/base/tax lines at adapter and database boundaries, absent mutation APIs, bindings and direct `VatOverview` integration. `RefreshDatabase` validates fresh schema and referential constraints.

No dashboard, Presentation, Relations/classification, VAT return boxes, projection or cache is included.
