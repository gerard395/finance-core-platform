# Architecture Decision Records

Dit gedeelte bevat beslissingen die de richting van Finance Core Platform structureren.

## Doel

- beslissingen expliciet vastleggen;
- rationale en impact documenteren;
- toekomstige ontwikkelaars een context bieden voor architectuurkeuzes.

## Aanbevolen structuur

Elke ADR bevat:

1. titel en datum;
2. context en probleemstelling;
3. overwogen opties;
4. gekozen aanpak;
5. consequenties en follow-up.

Gebruik bestandsnamen in de vorm `NNNN-korte-titel.md`. Een ADR krijgt één status: `Voorgesteld`, `Geaccepteerd`, `Afgewezen`, `Vervangen` of `Ingetrokken`. Geaccepteerde ADR's worden niet inhoudelijk herschreven; een nieuwe ADR vervangt de oude beslissing en verwijst ernaar.
